# Frontend guidelines

## Phase 23 — hosted mode integrity

The Render build is the standard non-static build: it must retain live/server labels and existing loading, token, provider-error, and model-error states. Do not remove or disguise the workspace-token prompt, NASA provenance, model limitations, or a provider failure merely because the app is hosted. The GitHub Pages static/replay labels apply only to the Pages build.

Phase 22: the Pages build must preserve the same loading/error/replay labels as the local app. No visual feature is added for deployment repair; do not hide static-mode limitations merely to make the hosted experience appear live.

Phase 20: Data & methodology shows “Browser snapshot cache”, count, approximate local size and newest-save time. Describe it as local/offline recovery only; use amber for stale data and neutral controls for clearing. The destructive clear button must say exactly what it clears and be disabled when empty. Do not call cache capacity cloud storage, backup, synchronization, fresh data or a security boundary. Stack summary/actions at 390px.

Phase 19: use the explicit label “Search saved cases” and include a clear button only while a query is active. Search result copy must say it searches saved record fields, not live satellite data. The next-check cue uses neutral/cyan styling and says “Next recorded check” or “All recorded checks marked”; it must never visually imply case closure, validation, emergency response or safety. Stack finder controls and cue text on mobile.

Phase 18: case return actions are secondary, explicit buttons labelled “Open saved evidence” and “Find in Mission control.” Nearby copy identifies the observation as a saved record. The order selector is labelled “Order cases” and changes presentation only. Never label sorting as dispatch order, risk order, priority recommendation or live status; preserve touch-size and stacked mobile actions.

Phase 17: workload status lanes and owner chips are filter buttons with visible selected state and accurate count labels. Checklist completion uses neutral/cyan progress treatment and always says “recorded checks”, never “case resolved” or “safe”. Do not use performance ranking, productivity claims, red urgency gradients, or false live-person indications. Stack lanes/chips and owner summaries on small screens.

Phase 16: cloud collaboration status is concise and factual: Firebase live, connecting, unconfigured, or unavailable. Never turn a transient listener state into an online-person indicator. Local/SQLite and Firebase activity must be source-labelled and deduplicated where the same update is seen through both paths. Cloud failure must not disable saving local case work.

Phase 15: present collaboration as a shared local activity trail, never a fabricated presence/presence count. Use concise timestamps, owner labels and self-declared-editor text. The Case desk pulse must offer manual refresh, state the 30-second local refresh behavior and fit a one-column mobile layout. Do not use alert/siren/message-notification styling or imply that a person has seen an update.

Phase 14: the comparison control is a labeled toggle, never an unlabeled checkbox. Use the existing cyan evidence accent for selected events and render at most two compact measurement cards. Clearly distinguish observed peak-FRP delta from a risk/safety conclusion. The tray must include remove/clear actions, keyboard focus visibility and a responsive one-column layout below 600px.

Phase 13: visual graphs with selectable categories use clear button affordances, focus rings and concise hover/keyboard labels. Their drill-down panel states the applied data slice and provides explicit "open queue" or "inspect evidence" actions; no click silently changes an analyst's filters. Location attention rank uses cyan for model evidence and amber only for high residuals, calls itself a report-local review ordering, displays its formula and limitation beside the list, and never uses red/danger/hazard language. Landing copy contrast uses translucent local gradients plus text shadow; avoid full-viewport opaque black overlays or discontinuous changes while the sticky Earth scrolls.

Phase 12 GIS: use cyan for selected geometry, lime for the manager/watch-area boundary, amber for stale/offline state and dashed neutral rings for planning distances. Label every layer, include its source/limitation, and preserve a readable geometry-first map when tiles fail. Do not use red cones, “threat radius”, sirens or dispatch language. The compact map toolbar must remain keyboard-operable and fit 390px.

Phase 11 design: deep near-black #071015, warm-white #edf4ee, lime #c5f277 action accent and cyan #60d5e5 data accent; amber for uncertainty. Oversized editorial landing typography, orbital arcs/grid geometry, large Earth backdrop and asymmetrical alternating text chapters. Sticky frosted navigation with logo/CompileX and accessible workspace links; never cover chapter text/CTAs with draggable canvas. Explicit motion toggle; reduced motion disables scroll parallax/dolly. Touch users retain natural vertical scrolling. Operational pages use consistent compact metric cards, clear left-to-right workflows, labels and contained tables, no fake gauges or made-up percentage confidence. Categorization badges say hypothesis/unverified, confirmed only from human review. All pages readable at 390px; command dialog traps focus, restores it on Escape; loading/error/empty views actionable.

Preserve current dark workspace and interactive Earth. Analysis uses charcoal panels, white primary text, muted gray supporting text, cyan for measured/model information and amber for unusual/stale/limited evidence. Do not use danger labels implying verified emergencies or green implying safety.

Use existing font and spacing; responsive cards, compact readable table with horizontal scroll contained inside its panel. No page overflow at 390px. Visible labels for inputs/file upload, focus outlines, semantic table headings, status aria-live and actionable error messages. Avoid fabricated progress bars; real stage names and elapsed duration are sufficient. Reduced-motion respects user settings.

Analysis layout: controls + provenance strip → observed metrics → temporal model evaluation and scatter plot → evidence table → expandable methodology/limitations. Clearly distinguish observed FRP (MW), modeled FRP (MW), residual percentile (not probability), in-sample/calibration/held-out status, and unavailable data. CSV/JSON report export separate from existing feed exports. Never silently fill missing data with regional constants.
