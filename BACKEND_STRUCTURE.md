# Backend structure

## Phase 23 — public runtime boundary

The Render service runs the existing Node process and its same-origin API. `PORT` is platform-assigned, `HOST` is `0.0.0.0`, and the already-public `/api/health` endpoint is the health probe. All other API routes retain token and same-origin enforcement. `WORKSPACE_TOKEN`, optional `FIRMS_MAP_KEY`, Firebase variables, SQLite `data/`, and analysis artifacts are runtime-only; none enter the image source or Git history. SQLite is not persistent on Render free instances, so durable storage needs a later managed database design rather than an unsupported filesystem promise.

Phase 22 adds no API, database or server logic. GitHub Pages hosts compiled public files only; static API/replay behavior is the existing client build boundary.

Phase 20 has no server/database change. Browser-only cache records hold only validated public live feed snapshots under the existing ThermalGuard key. Cache summary/clear are client operations; clear removes that one local key and never invokes an API. Cache compaction uses `savedAt`, current query key and serialized byte count; it never changes a feed payload or server-side cache.

Phase 19 adds no persistence, route or server query. `caseSearchText` and `nextRecordedCheck` are client-only projections of existing case fields. They neither patch the checklist nor change activity; a fully marked checklist is a record state only.

Phase 18 introduces no API/database schema change. The existing persisted case `event` object remains the sole source for evidence return. Client ordering consumes `status`, `updatedAt` and verification checklist fields and never writes a result or modifies case history.

Phase 17 adds no persistence or route. `caseBoard(cases)` is client-only and returns counts per allowed saved status, owner workload and checklist totals. “Unassigned” is a grouping label for an absent/explicit unassigned assignee, not an identity. It never writes status, assignment or checklist progress.

Phase 16 introduces a browser Firestore mirror only. It writes sanitized case `{id,title,eventId,lat,lon,lastSeen,maxFrp,status,assignee,note,checklist,updatedAt,actor}` documents to `workspaces/thermal-guard/cases/{caseId}` and immutable compact activity `{caseId,caseTitle,actor,text,occurredAt}` documents to `workspaces/thermal-guard/activities/{caseId}_{occurredAt}`. No FIRMS raw observations, XGBoost report, contacts, keys, token, entire event detections or private directory information are mirrored. Firebase writes are non-blocking after successful local API persistence. Anonymous Auth identifies a browser only; it does not validate an analyst identity. `firestore.rules` requires a signed-in Firebase user for the namespace. No Firebase Admin SDK/server key is used.

Phase 15 extends stored case activity entries to `{at, actor?, text}`. On a create/update, `actor` is an optional validated 80-character self-declared editor string; it is written as record metadata and is not authentication. Existing activity without actor remains valid. `PATCH /api/cases/:id` accepts `actor` alongside status/assignee/note/checklist, appends changed-field events with actor and retains the existing 200-entry cap. No new endpoint, websocket, notification or user table is introduced.

Phase 14 comparison is local React state containing at most two existing event IDs. It reads only current `feed.events` fields already received by `/api/events`, does not add an endpoint and does not write to reviews/cases/history/model records. On a feed refresh, stale IDs are omitted by the render projection rather than reconstructed from cached event data.

Phase 13 has no new API, model training or persistence. `locationRank(report)` is a client-only derived view over completed report rows that have an existing NASA `eventId`: per event, maximum residual percentile × 0.70 plus report-normalized log(1 + maximum observed FRP) × 30. It carries source row count/coordinates and can only open existing evidence. It must not overwrite rule priority, review status or any server record. The computation is unavailable for uploaded rows without event IDs and must be labelled as a within-report investigation ordering, not a danger/hazard metric.

Phase 12 has no new remote API or server persistence. The browser may store the last successful `/api/events` response by sanitized source/window/bbox key with a retrieval timestamp. It only restores the exact matching query when live retrieval fails/offline; metadata is marked `cached:true`, `stale:true`, `offlineSnapshot:true` and cannot trigger automatic analysis. GeoJSON export is generated client-side only from the already visible boundary and observation coordinates.

Phase 11 verification correction: full-stack startup defaults `ALLOW_OFFLINE_CACHE` to false; only explicit `true` enables the existing timestamped fallback. Tests may opt into fallback through `createApplication({allowOfflineFallback:true})`. Archived history remains separate from the live feed.

## Phase 11 contracts

Response-context refresh accepts `refresh=1` to bypass its 15-minute cache while retaining coalescing/rate limits. Overpass uses a bounded GET query with default body plus center output so node coordinates and way/relation centers are retained. A rapid new selection retries a throttled lookup once after three seconds. Provider errors are explicit.

Add observation_history(id TEXT,provenance TEXT,payload TEXT,acquired_at TEXT,source TEXT,lat REAL,lon REAL, PRIMARY KEY(id,provenance)); NASA live detections archive during retrieval, no replay. Imported validated FIRMS rows use provenance=user-import and cannot replace NASA history. GET /api/history?source&bbox&provenance returns monthly medians/counts/observedDays and first/last, max 50k rows, explicit sampled-limit warning. POST /api/history/import {source,csv} max 2MB,15k rows, validates using existing normalization, preserves quality counters. Monthly percentage=100*(recent median-baseline median)/baseline median, minimum 10 detections on 3 observed days in each period; no value at zero baseline; same source/provenance/extent only. Never interpreted as production.

GET /api/response-context?lat&lon: parallel Overpass (5 km) and Open-Meteo current modeled weather requests, bounded timeout and response size, independent errors. OSM includes emergency=fire_hydrant, amenity=fire_station/hospital, office=government, industrial/landuse crop/forest and gas-flare tags. Results include resource type/id/ref/name/lat/lon/distanceKm/phone/sourceUrl; preserve nulls. Cache context 15 minutes, coalesce per coordinate; request rate bounded. No arbitrary external URL fetching; user-supplied contact source URLs only stored as validated HTTPS links.

contacts(id TEXT PK,payload TEXT,created_at TEXT): GET/POST /api/contacts. Required name,role,phone,lat,lon,sourceUrl,verifiedBy,verifiedOn; locally self-attested, not independently validated by ThermalGuard. cases(id TEXT PK,payload TEXT,updated_at TEXT): GET/POST /api/cases; PATCH /api/cases/:id. Required existing NASA event id on create, title/assignee optional; status new/investigating/monitoring/closed; checklist timestamp/source/context/contact/fieldVerification boolean; notes max2000; append before/after activity metadata (no caller-supplied event snapshots). Contacts/cases use same token/origin/body safeguards; shared prototype workspace is not role authorization. No deletions, calls or messages.

Client evidence hypotheses: transparent rules over real residual/history + optional OSM tags. XGBoost remains regression, NOT a trained six-class classifier. With insufficient context the result is Uncertain / Other. Candidate flare/process/industrial/crop/forest classes always unverified; historical repetition does not prove routine operation. No auto-save human confirmation. Automatic jobs keyed by selected source/window/extent and detection inputs; once per observed fingerprint, manual retry allowed; mounted live workspace only, no hidden cron. Current weather is displayed with timestamp and not retroactively assigned to satellite overpass.

Existing SQLite: snapshots(key TEXT PK,payload TEXT,saved_at TEXT); event_records(id TEXT PK,payload TEXT); reviews(id INTEGER PK,event_id TEXT,status TEXT,classification TEXT,note TEXT,analyst TEXT,created_at TEXT); areas(id TEXT PK,name TEXT,bbox TEXT,created_at TEXT). Reviews reference retrieved events logically; prepared statements and WAL remain. Analysis adds analysis_runs(id TEXT PK,payload TEXT,created_at TEXT), retaining completed/failed job metadata and report (no uploaded raw CSV). Model artifact written under data/analysis/<UUID>/model.json.

Existing routes: GET /api/health, GET /api/events?source&days&bbox&mode; GET/POST /api/events/:id/reviews; GET /api/context?lat&lon (OSM, never asserted facility identity); GET/POST /api/areas; DELETE /api/areas/:id. Shared token (optional locally), same-origin checks and rate limits remain.

New routes: POST /api/analysis/jobs accepts {source: NOAA20|NOAA21|SNPP,days:1|2|7,bbox:[w,s,e,n],csv?:string}; max 2 MB CSV, bounded total JSON body. Returns 202 {id,status,stage,startedAt}. GET /api/analysis/jobs/:UUID returns job {id,status,stage,startedAt,finishedAt?,elapsedMs,error?,result?}. Status queued/running/completed/failed. One concurrent heavy job; requests above capacity return 429. Poll only the known job. Failed jobs never return substitute scores. Reject replay input. Use fixed executable/script paths and spawn without shell; JSON via stdin, timeout, output limit, child cleanup.

Training is a seven-day regional NASA request for selected sensor; input/output provenance includes quality counters and stale flags. Train first UTC days, calibrate penultimate UTC day, test final UTC day (minimum 4 days; >=100 training and >=20 calibration/test rows). FRP target transformed log1p; features never include FRP, a label derived from FRP, weather or guessed land cover. Required complete radiometry/geometry rows only. Calibrate positive log residual percentile against calibration residuals; this is an empirical ranking, not calibrated fire probability. Observations on training/calibration dates are explicitly marked. Held-out metrics use unseen final day and compare a training median baseline. Nearby history considers only strictly earlier UTC days within 5 km from available feed, not a 30/365-day baseline. No-detection is not no-fire.

Input validation bounds (prototype guardrails, not official NASA quality flags): I4/I5 brightness 150–500 K, scan/track 0.01–5 km, valid global coordinates, D/N flag; FRP finite and nonnegative. Missing values are excluded, not filled. At most 50,000 training and 15,000 scoring rows per run. Features outside the training min/max are explicitly flagged even when within validation bounds. Python worker receives JSON only via stdin, supports cancellation on server close, returns bounded JSON, and cannot execute user-supplied paths or commands. Hyperparameters: 140 trees, depth 4, eta 0.06, row/column sampling 0.9, CPU hist method, seed 42, two threads. These settings are fixed before temporal evaluation.

Result: model version/split/metrics/importance/domain; rows {id,eventId?,lat,lon,acquiredAt,observedFrp,expectedFrp,residualPercentile,split,baseline,flags}; input/source metadata; real processing timings; source classification remains unverified. Uploaded CSV never replaces NASA training and has unverified provenance. Persisted reports retain source timestamps; each model artifact has an adjacent exact normalized training.json matching the report digest. Serialize JSON finite numbers only. Local user reviews are not ML labels. Reports/model artifacts are retained until manually archived; repeated runs consume local disk. Interrupted jobs return a restart/rerun message. The final test UTC day may be partial; no completed-day assumption is made.
