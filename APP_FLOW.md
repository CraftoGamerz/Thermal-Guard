# Application flow

Phase 20 cache flow: successful live query → validate and compact the exact-query browser snapshot cache → retain newest entries only within count/byte limits. Offline/fetch failure → restore only the matching saved snapshot and mark it stale with its save time; otherwise show the existing no-snapshot state. Data & methodology → browser cache panel shows local count/size/newest entry → user may explicitly clear only the local ThermalGuard snapshots; clearing cannot touch server records, Firestore, cases, reviews or source data.

Phase 19 retrieval flow: Case Desk → enter words, owner or saved coordinates in Case search → existing status/owner filters and case order apply to the matched saved cards → clear search restores the previous board-filtered set. Each case shows the first unmarked recorded check as a prompt for human work; if all current checks are marked it says only that the record is complete, not that the observation is resolved, safe or current.

Phase 18 evidence-return flow: Case desk → choose “Open saved evidence” to inspect the case's preserved NASA observation in the existing drawer, or “Find in Mission control” to focus that observation before navigating there. Case ordering only changes the visible saved-card sequence; filters, record contents and server state do not change. An old case remains historical evidence and is never presented as a current live detection.

Phase 17 workload flow: Case desk → live workload board → select a status lane or owner chip → existing Case cards filter immediately → clear board filter restores all saved cases. Board values update from the same local/Firestore-refreshed records as the cards. Completion reflects only the saved verification checklist; it neither closes a case nor makes a safety/priority conclusion.

Phase 16 Firebase flow: local Case desk opens → if Firebase config exists, Anonymous Auth connects → Firestore activity listener enters connecting/live/error state → local saved case activity is mirrored to Firestore → any subscribed browser receives real snapshot updates. If config/Auth/Firestore rules/database are unavailable, Case desk remains usable with SQLite/local polling and clearly says cloud sync is unavailable; it does not manufacture remote data. Firebase activity is a compact collaboration mirror, not a replacement for the local case detail or NASA/XGBoost APIs.

Phase 15 collaboration flow: Case desk → shared local workspace header → persisted team pulse and open-case owner summary. Opening Case desk starts a 30-second cases refresh only for this tab; manual refresh is always available. Saving a case attaches the current self-declared manager/workspace editor to the activity entry. Another client on the same local server sees the new entry after its next refresh/poll. Replay/static does not show simulated team presence or collaboration data. Editor names describe the submitted record only; they do not authenticate the person.

Phase 14 comparison flow: Review queue → select Compare on one event → tray states that one more location may be selected → select a second event → side-by-side measured observation comparison, optional evidence links, clear/remove controls. A third selection replaces the older one after an explicit live status message; nothing is submitted or persisted. If a refresh removes a selected event, the tray shows only the still-visible selection or closes. The tray compares measurements and saved review state only; it does not recommend action or establish a relationship between locations.

Phase 13 interaction flow: Overview and Analytics chart items are buttons, not passive bars. Selecting an acquisition hour, priority or confidence value opens a compact drill-down with matching event/detection count, an explicit observation/filter description, the strongest matching event where present, and buttons to either apply that filter in Review queue or inspect its evidence. In Smart Analyser, selecting a scatter point opens its raw evidence detail. A completed NASA report may show Location attention rank: select a rank row to open that report event's evidence. The score compares only scored locations in that report (70% maximum calibrated residual percentile + 30% normalized log observed FRP); it never triggers a queue action automatically, labels an area dangerous, confirms a source, or persists a new decision. CSV rows without NASA event IDs have no location list.

Landing chapter flow keeps its sticky Earth and scroll-driven camera movement. Text contrast is provided by local, soft surfaces/text shadow rather than a full-width black overlay that changes as chapters switch. Motion indicators are decorative status feedback only; reduced-motion disables their transition.

Phase 11 discovery: the landing hover/focus/tap feature guide explains automatic scoring, six hypotheses, response resources, weather, cases and historical trends. The API explorer includes their actual routes. The existing satellite walkthrough and priority sandbox remain educational illustrations, not live measurements.

Workspace destination changes return to the top of the page. Current human reviews override older automatic-report event snapshots in Mission control; an unchanged observation does not need model retraining to display a new review.

Phase 12 map flow: Overview always draws the selected manager/watch extent as a GIS boundary. While online it requests fresh NASA observations and selected basemap tiles. After a successful live response, a bounded browser snapshot is retained by source/window/extent. On a failed request or offline browser state, the matching snapshot is restored with its retrieval time and stale warning; otherwise the map displays the assigned boundary, coordinates and an honest empty state. Selecting an observation can show distance-only planning rings (1/3/5 km); these are not plume, evacuation or impact zones. The user can copy coordinates or download the visible event/boundary layer as GeoJSON.

## Phase 11 active flow

Sticky Earth landing → three scroll chapters (Observe / Understand / Coordinate), team/nav → existing pages plus Mission control (#mission), Response resources (#resources), Activity trends (#trends), Case desk (#cases). Cmd/Ctrl+K opens searchable navigation, Escape closes and restores focus. Team identity is CompileX; supplied contributor names remain as given in conversation.

All live workspace pages share automatic XGBoost state. A successful changed-data fingerprint triggers once, job status polls, failure exposes retry; unchanged feed does not retrain. Toggle pauses new jobs, not already accepted computation. Replay/static/offline disables new live analysis. Source/area/window changes invalidate displayed results. Smart Analyser keeps explicit CSV/manual runs as well; automatic result can be opened from Mission control.

Mission control → threshold/suspicions → select event → six hypotheses/reasons → Resources or create case. Resources defaults to selected event or area center; loading shows real provider work; OSM and weather failures are independent. Contacts/asset refs distinguish unverified mapping from locally user-verified directory. Local contact creation requires source URL and verification date/name; never calls on save. Case desk → update status/assignee/notes/checklist → persist activity log → export JSON. Cases do not imply emergency dispatch or reviewed source truth.

Trends → sensor/extent + provenance source (NASA archive or uploaded unverified CSV) → monthly count/median FRP/observed days → pick two available periods → thermal change %. Empty/insufficient data explains import option; no production inference. Historical imports never populate live maps or train XGBoost. Strict live feed fails offline; historical archive is explicitly historical and accessible separately.

Authoritative active scope: PRD real-observation analysis, phase 10.

Landing Earth → guest or public-PIN demo manager → Overview / Review queue / Analytics / Watch areas / Data & methodology / Smart Analyser. Preserve current Earth, map and navigation. Manager is a demonstration state, not authentication. Node API may require a shared workspace token; 401 opens connection settings.

Smart Analyser uses the workspace sensor, time window and area. NASA feed → Run real analysis → queued/fetching NASA/training and scoring/completed or failed. Poll job status, retain report on successful completion; dismiss stale requests on area/source/window changes or unmount. Do not show made-up progress. Report contains acquisition/retrieval provenance, quality counts, measured elapsed times, temporal evaluation, feature importance, observed-versus-modeled chart, searchable anomaly evidence table and JSON/CSV exports. Evidence buttons open existing review drawer for NASA events.

Optional CSV mode → file selection (2 MB limit) → parse/validate on server → score against NASA-trained model. Required FIRMS columns: latitude, longitude, frp, acq_date, acq_time, bright_ti4, bright_ti5, scan, track, daynight. Source selected explicitly. Uploaded provenance is unverified; CSV observations cannot create reviewable NASA records. Show rejected/duplicate/missing-feature counts. Empty extent is valid; insufficient training data or no valid scoring rows produces a clear error.

Static Pages/replay → show unavailable real-analysis notice and full-stack setup guidance, never fall back to mock ML. Outage with a real cached snapshot → prominent stale warning in report. Missing Python/runtime → setup error; competing job → 429, retry later. Models are exploratory, source classes remain Uncertain / Other until human review. An in-sample/calibration result must not be mistaken for independent testing.
